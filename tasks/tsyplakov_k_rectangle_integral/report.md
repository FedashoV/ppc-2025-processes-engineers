## 1. Введение 

В данной работе необходимо реализовать вычисление многомерного интеграла с использованием многошаговой схемы (метод прямоугольников) в параллельной среде. Основной целью является освоение методов параллельного программирования и распределения вычислительной нагрузки между процессами.

Программа должна корректно работать для многомерных функций, поддерживать произвольное количество шагов по каждой оси и обеспечивать точное вычисление интеграла с допустимой погрешностью.

## 2. Постановка задачи 

На вход программы подаётся многомерная область интегрирования, заданная в виде вектора границ по каждой размерности, а также количество шагов разбиения сетки. Необходимо вычислить многомерный интеграл функции методом прямоугольников.

Требуется реализовать две версии алгоритма:

1. Последовательную – вычисление суммы значений функции во всех точках сетки на одном процессе.
2. Параллельную с использованием MPI – разбиение точек интегрирования между процессами, вычисление локальных сумм и сбор результата на всех процессах.

Результатом работы алгоритма является значение интеграла, вычисленное с использованием выбранного числа шагов по каждой размерности, при этом параллельная версия должна корректно объединять локальные вычисления всех процессов для получения точного результата.

### Дополнительные требования и ограничения:

- Алгоритм должен поддерживать передачу массивов типов ```MPI_INT```, 
```MPI_FLOAT``` и ```MPI_DOUBLE```;
- Реализация параллельного алгоритма должна использовать только функции точечной 
передачи сообщений ```MPI_Send``` и ```MPI_Recv```, без применения коллективных 
операций MPI;
- Передача данных в параллельной версии должна 
выполняться с использованием древовидной схемы взаимодействия процессов, 
обеспечивающей логарифмическую сложность по числу процессов;
- Алгоритм должен корректно работать для произвольного номера корневого 
процесса ```root```;
- Для одинаковых входных данных последовательная и 
параллельная реализации должны возвращать одинаковый результат;
- Параллельная реализация должна корректно работать 
при любом количестве процессов и размерах передаваемых данных.

## 3. Базовый алгоритм

Базовый алгоритм заключается в вычислении многомерного интеграла методом прямоугольников. Каждый процесс вычисляет значение функции в своей части сетки точек и суммирует результаты. В параллельной версии локальные суммы объединяются, чтобы получить итоговое значение интеграла.

### Последовательная версия алгоритма

В последовательной версии предполагается выполнение программы на одном процессе. В этом случае интеграл вычисляется путём обхода всех точек сетки по всем измерениям и суммирования значений функции, умноженных на объём элементарного прямоугольника.

В конструкторе принимаются границы интегрирования и количество шагов по каждой оси, выходное значение интеграла инициализируется нулём:

```
TsyplakovKRectangleIntegralSEQ::TsyplakovKRectangleIntegralSEQ(const InType& in) {
  SetTypeOfTask(GetStaticTypeOfTask());
  GetInput() = in;
  GetOutput() = 0.0;
}
```

В методе ```RunImpl``` выполняется обход всех точек сетки и суммирование значений функции:

```
bool TsyplakovKRectangleIntegralSEQ::RunImpl() {
  const auto& input = GetInput();
  const int dim = (input.size() - 1) / 2;
  const int steps = static_cast<int>(input.back());
  std::vector<double> a(dim), b(dim), h(dim);

  for (int i = 0; i < dim; ++i) {
    a[i] = input[2 * i];
    b[i] = input[2 * i + 1];
    h[i] = (b[i] - a[i]) / steps;
  }

  double sum = 0.0;
  for (int idx = 0; idx < std::pow(steps, dim); ++idx) {
    int tmp = idx;
    double f_val = 0.0;
    for (int d = 0; d < dim; ++d) {
      int coord = tmp % steps;
      tmp /= steps;
      double x = a[d] + coord * h[d];
      f_val += x; // пример функции f(x) = x_1 + x_2 + ... + x_n
    }
    sum += f_val;
  }

  double volume = 1.0;
  for (int d = 0; d < dim; ++d) volume *= h[d];
  GetOutput() = sum * volume;
  return true;
}
```
### Параллельная версия алгоритма

В параллельной версии каждый процесс отвечает за вычисление интеграла на части сетки точек. Алгоритм выполняется следующим образом:

#### Инициализация MPI:
Каждый процесс получает свой номер (rank) и общее количество процессов (size).

#### Разбиение области интегрирования:
На основе входного вектора вычисляются границы интервалов по каждому измерению и шаг сетки h[i]. Общее количество точек сетки равно steps^dim.

#### Назначение диапазона точек процессу:
Все точки сетки равномерно делятся между процессами. Если общее количество точек не делится на число процессов, остающиеся точки распределяются по рангу процессов:

```
start = rank * points_per_proc + std::min(rank, remainder);
end = start + points_per_proc + (rank < remainder ? 1 : 0);
```

#### Вычисление локальной суммы:

Каждый процесс обходит свои точки сетки, вычисляет значение функции и суммирует их:

```
for (int idx = start; idx < end; ++idx) {
    // преобразование индекса в координаты
    // вычисление значения функции
    local_sum += f_value;
}
```

#### Сбор результатов и умножение на объём:

Локальные суммы собираются на корневом процессе с помощью MPI_Reduce, результат умножается на объём элементарного прямоугольника:

```
MPI_Reduce(&local_sum, &global_sum, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);
if (rank == 0) {
    result = global_sum * volume;
}
```

#### Распространение результата на все процессы:

Для того чтобы все процессы имели доступ к итоговому значению интеграла, выполняется ```MPI_Bcast```:

```
MPI_Bcast(&result, 1, MPI_DOUBLE, 0, MPI_COMM_WORLD);
GetOutput() = result;
```

Алгоритм обеспечивает равномерное распределение работы между процессами, масштабируемость при увеличении числа процессов и размерности интеграла, а также корректное вычисление результата для произвольных чисел шагов и границ интегрирования.

## 4. Схема распараллеливания.



### 1. Инициализация MPI

Все процессы участвуют в выполнении 
параллельного алгоритма и вызывают стандартные функции инициализации MPI:

- ```MPI_Comm_rank``` — для определения номера текущего процесса ```(rank)```;
- ```MPI_Comm_size``` — для определения общего количества процессов ```(size)```;

Обмен сообщениями выполняется в рамках коммуникатора ```MPI_COMM_WORLD```.

### 2. Получение входных данных

Каждый процесс получает общий вектор входных данных ```input```, который задаёт:

границы интегрирования для каждой размерности ```(a[i], b[i])```;

количество шагов по каждой размерности (в последнем элементе вектора ```steps```).

Входные данные одинаковы для всех процессов. Каждый процесс будет работать только с частью сетки точек.

### 3. Подготовка данных к передаче

Общее количество точек сетки вычисляется как ```total_points = steps^dim```, где ```dim``` — размерность интеграла.

Для распределения работы:

- каждая точка сетки получает уникальный индекс ```idx принадлежит [0, total_points)```;
- каждый процесс обрабатывает диапазон точек ```[start, end)```:

```
points_per_proc = total_points / size;
remainder = total_points % size;
start = rank * points_per_proc + min(rank, remainder);
end = start + points_per_proc + (rank < remainder ? 1 : 0);
```

Такое распределение обеспечивает равномерную нагрузку среди процессов, даже если ```total_points``` не делится на ```size```.



### 4. Локальное вычисление интеграла

Каждый процесс:

- проходит по своему диапазону точек;
- преобразует индекс точки ```idx``` в координаты в каждой размерности;
- вычисляет значение функции в точке;
- суммирует локальные значения в переменную ```local_sum```;

Таким образом каждый процесс получает частичную сумму интеграла на своём подмножестве точек.

### 5. Агрегация данных на промежуточных узлах

После локального подсчёта выполняется коллективная операция:

- ```MPI_Reduce``` суммирует локальные интегралы всех процессов и передаёт результат корневому процессу ```rank == 0```;
- на корневом процессе результат умножается на объём элементарного прямоугольника:

```
volume = h[0] * h[1] * ... * h[dim-1];
result = global_sum * volume;
```


### 6. Распространение результата на все процессы

Чтобы каждый процесс имел доступ к итоговому значению интеграла, используется:

```
MPI_Bcast(&result, 1, MPI_DOUBLE, 0, MPI_COMM_WORLD);
```

Все процессы получают вычисленный интеграл, и его значение записывается в ```GetOutput()```.

### 7. Особенности параллельной топологии

- Алгоритм не требует выделенного управляющего процесса, но корневой процесс ```(rank == 0)``` выполняет агрегацию локальных сумм и умножение на объём.
- Локальные вычисления полностью независимы, что обеспечивает хорошую масштабируемость.
- Сбор результатов реализован через стандартные коллективные операции MPI ```(Reduce и Bcast)```, что упрощает синхронизацию и гарантирует корректность результата.

### Важные допущения и частные случаи:
При реализации параллельного вычисления многомерного интеграла методом прямоугольников были приняты следующие допущения и учтены граничные случаи:
#### 1. Корректность входных данных
Предполагается, что вектор входных данных содержит корректные границы интегрирования для каждой размерности (a[i], b[i]) и положительное число шагов по каждой размерности ```(steps > 0)```. Некорректные данные приводят к остановке алгоритма.

#### 2. Размерность интеграла
Алгоритм рассчитан на произвольное количество размерностей ```dim ≥ 1```. Каждый процесс использует одинаковый набор границ и шагов, обеспечивая корректное разбиение сетки точек.

#### 3.Разбиение сетки точек
Общее количество точек ```total_points = steps^dim``` распределяется между процессами. Каждый процесс получает последовательный диапазон точек ```[start, end)```, что обеспечивает равномерную нагрузку, даже если ```total_points``` не делится на число процессов.

#### 4. Локальная независимость
Каждый процесс вычисляет интеграл только на своём диапазоне точек. Нет необходимости в обмене данными до этапа агрегации, что минимизирует коммуникационные задержки.

#### 5. Сбор результатов
Агрегация локальных сумм выполняется с помощью ```MPI_Reduce```. Корневой процесс ```(rank == 0)``` умножает сумму на объём элементарного прямоугольника, формируя итоговый интеграл. Алгоритм корректно работает для любого количества процессов ```P ≥ 1```.

#### 6. Распространение результата
Использование ```MPI_Bcast``` гарантирует, что все процессы получают вычисленный интеграл после завершения ```Reduce```, что позволяет использовать результат на любом процессе без дополнительного обмена.

### Пространственная и временная сложности алгоритмов

Последовательная версия:

- Временная сложность: ```O(steps^dim)```, так как требуется пройти все точки сетки.
- Пространственная сложность: ```O(dim)```, для хранения границ и шага по каждой размерности.

Параллельная версия:

Параллельная версия:

- Временная сложность: ```O(steps^dim / P)```, где P — количество процессов. Каждый процесс вычисляет только свою часть сетки.
- Пространственная сложность: ```O(dim + 1)```, где dim — размерность интеграла, +1 для хранения локальной суммы. На корневом процессе добавляется дополнительная память для хранения глобального результата.

Таким образом, алгоритм эффективно масштабируется по числу процессов и использует минимальный объём памяти на каждом процессе, при этом обеспечивая корректное и полное вычисление многомерного интеграла.

#### Особенности параллельной реализации

Использование распределения точек интегрирования между процессами обеспечивает равномерную нагрузку.
Применение ```MPI_Reduce``` и ```MPI_Bcast``` позволяет избежать ошибок синхронизации и гарантирует корректное получение результата на корневом процессе.

Временные затраты на передачу данных незначительны по сравнению с вычислительной нагрузкой, поэтому масштабирование на малом и среднем количестве процессов эффективно.

#### Общий итог
Таким образом, параллельная реализация метода прямоугольников позволяет существенно ускорить вычисление многомерных интегралов без потери точности. Алгоритм демонстрирует хорошую масштабируемость и может быть использован для более крупных интегралов и большей размерности задачи.
