## 1. Введение  
---
В данной работе изучается задача определения пары соседних элементов вектора с наименьшей разницей между их значениями. Основная цель — реализовать как последовательный, так и MPI-параллельный алгоритм, провести сравнение их производительности на векторах различной длины и оценить, как обмен данными между процессами влияет на масштабируемость решения.

## 2. Постановка задачи
---
На вход подается вектор целых чисел. Необходимо определить такой индекс i, для которого разница между элементами с индексами i и i+1 минимальна. В качестве результата возвращается кортеж индексов (i, i+1).

### Дополнительные требования и ограничения:
1. Если встречаются несколько пар с одинаковой минимальной разницей, выбирается пара с индексом, который ближе к 0 (к началу вектора);
2. Алгоритмы должны корректно обрабатывать любые значения элементов вектора;
3. Для одинаковых входных данных последовательная и параллельная реализации должны возвращать одинаковый результат;
4. Параллельный алгоритм реализуется с использованием MPI и должен правильно работать.

## 3. Базовый алгоритм
---
Концепция такова, чтобы за один проход по вектору вычислить наименьший модуль разности соседних элементов. 

### Ход работы:
1. В конструкторе принимаем на вход вектор, а на выход ставим по умолчанию (-1, -1), что означает, что нету такой пары, которая удовлетворяла бы поставленную цель.
```
TsyplakovKVecNeighboursSEQ::TsyplakovKVecNeighboursSEQ(const InType& in) {
  SetTypeOfTask(GetStaticTypeOfTask());
  GetInput() = in;
  GetOutput() = std::make_tuple(-1, -1);
}
```

2. Реализуем поиск пары с минимальной разницей по значению. Создаём переменные, которым присваиваем по умолчанию значения - индексу -1, а минимальной разнице MAX_INT (самое большоре число типа int).
```
bool TsyplakovKVecNeighboursSEQ::RunImpl() {
  const std::size_t n = vector_data_.size();

  if (n < 2) {
    GetOutput() = std::make_tuple(-1, -1);
    return true;
  }

  int min_diff = std::numeric_limits<int>::max();
  int min_index = -1;

  for (std::size_t i = 0; i + 1 < n; ++i) {
    int64_t diff = std::llabs(static_cast<int64_t>(vector_data_[i + 1]) - static_cast<int64_t>(vector_data_[i]));

    if (diff < min_diff || (diff == min_diff && std::cmp_less(i, static_cast<std::size_t>(min_index)))) {
      min_diff = static_cast<int>(diff);
      min_index = static_cast<int>(i);
    }
  }

  if (min_index >= 0) {
    GetOutput() = std::make_tuple(min_index, min_index + 1);
  } else {
    GetOutput() = std::make_tuple(-1, -1);
  }

  return true;
}
```
Конечно же, учитываем ситуацию, когда размер вектора меньше двух.

## 4. Схема распараллеливания
Алгоритм параллельного поиска минимальной разницы соседних элементов

### 1. Инициализация MPI:
Все процессы запускаются в коммуникаторе MPI_COMM_WORLD. Каждый процесс получает свой ранг (my_rank) и общее количество процессов (world_size).

### 2. Проверка входных данных:
Вектор элементов arr извлекается через GetInput(). Если размер вектора меньше 2, функция сразу возвращает результат (-1, -1) и завершает выполнение, так как соседних элементов для сравнения нет.

### 3. Распределение работы между процессами:
Каждый процесс обрабатывает элементы с шагом, равным числу процессов:
```
for (int idx = my_rank; idx < n - 1; idx += world_size)
```

Таким образом, индексы распределяются равномерно, и каждый процесс проверяет «свою» подмножину пар соседних элементов.

### 4. Локальный поиск минимума:
Для каждой пары соседних элементов процесс вычисляет абсолютное значение разницы:
```
int diff = std::abs(arr[idx] - arr[idx + 1]);
```

Если найденная разница меньше текущего локального минимума best_local_gap, процесс обновляет локальный минимум и индекс:
```
if (diff < best_local_gap) {
    best_local_gap = diff;
    best_local_pos = idx;
}
```

### 5. Агрегация результатов:
После обработки всех локальных пар происходит глобальное сравнение локальных минимумов с помощью MPI_Allreduce:
```
MPI_Allreduce(&best_local_gap, &best_global_gap, 1, MPI_INT, MPI_MIN, MPI_COMM_WORLD);
```

Все процессы узнают минимальное значение разницы среди всех пар.

Затем определяется кандидат на глобальный индекс:
```
int candidate_index = std::numeric_limits<int>::max();
if (best_local_gap == best_global_gap) {
    candidate_index = best_local_pos;
}
```

И выполняется ещё одно MPI_Allreduce для выбора минимального индекса среди всех кандидатов:
```
MPI_Allreduce(&candidate_index, &final_index, 1, MPI_INT, MPI_MIN, MPI_COMM_WORLD);
```

### 6. Формирование выходных данных:
После получения глобального индекса соседние элементы формируют пару:
```
GetOutput() = std::make_tuple(final_index, final_index + 1);
```

Если глобальный минимум не найден, результат остаётся (-1, -1).

### 7. Особенности параллельной топологии:
Все процессы равноправны для локальных вычислений и участия в MPI_Allreduce. Root-процесс (rank=0) не выполняет отдельного распределения данных, так как индексы распределяются через шаг idx += world_size. В итоге каждый процесс имеет доступ к глобальному результату минимальной пары соседних элементов.

### Особые случаи

Особые ситуации в параллельной обработке возникают при работе с элементами, которые потенциально могут образовать минимальную разницу на границах диапазонов, обрабатываемых разными процессами.

### 1. Распределение индексов между процессами:
Каждый процесс обрабатывает свои индексы с шагом, равным числу процессов:
```
for (int idx = my_rank; idx < n - 1; idx += world_size)
```

Такой способ распределения обеспечивает равномерную нагрузку, но требует учёта того, что соседние элементы могут находиться на разных процессах.

Вычисление локального минимума:
Для каждой «своей» пары соседних элементов процесс вычисляет разницу и обновляет локальный минимум:
```
if (diff < best_local_gap) {
    best_local_gap = diff;
    best_local_pos = idx;
}
```

Если разница равна текущему локальному минимуму, выбирается пара с наименьшим глобальным индексом.

### 2. Обработка пограничных элементов:
В оригинальной реализации с блоками, где процессам выделяются непрерывные поддиапазоны, требуется обмен граничными элементами между соседними процессами для корректного учета минимальных разниц на границах:
```
// левый и правый граничные элементы
int left_value  = (local_start > 0) ? vec[local_start] : 0;
int right_value = (local_end < global_size) ? vec[local_end - 1] : 0;

// обмен с соседями
MPI_Irecv(...);
MPI_Isend(...);
MPI_Waitall(...);

// проверка разниц на границах
if (rank > 0) { ... }
if (rank + 1 < comm_size) { ... }
```

### 3. Глобальная агрегация:
После локального подсчёта всех «своих» разниц и учёта пограничных значений, глобальный минимум и соответствующий индекс выбираются через MPI_Allreduce:
```
MPI_Allreduce(&best_local_gap, &best_global_gap, 1, MPI_INT, MPI_MIN, MPI_COMM_WORLD);
MPI_Allreduce(&candidate_index, &final_index, 1, MPI_INT, MPI_MIN, MPI_COMM_WORLD);
```

Это гарантирует, что глобальный результат будет одинаковым на всех процессах.

### 4. Результат:
Глобальная минимальная пара соседних элементов формируется как ```(final_index, final_index + 1)``` и сохраняется в GetOutput(). В случае отсутствия минимальных пар результат остаётся (-1, -1).

### Пространственная и временная сложности алгоритмов

<b>Последовательная версия:</b>

Временная сложность составляет ```O(N)```, где  ```N``` - размер вектора.\
Пространственная сложность - ```O(N)```, где ```N``` - размер вектора индексов, равный размеру входного вектора.

<b>Параллельная версия:</b>

Временная сложность - ```O(N/P + log(P))```, где ```N``` - размер вектора, ```P``` - количество процессов, ```log(P)``` - сложность операции ```MPI_Reduce```.\
Пространственная сложность - ```O(N/P)``` на процессах, связанных с вычислениями и ```O(N)``` на Root-процессах.

## 8. Выводы
---

В рамках работы был разработан и протестирован алгоритм поиска пары соседних элементов вектора с минимальной разницей значений, реализованный как в последовательной, так и в параллельной версиях.

Параллельная реализация позволила распределить вычислительные задачи между несколькими процессами и сократить время выполнения, однако полученное ускорение оказалось ограниченным. Наибольший прирост производительности наблюдается при использовании двух процессов, в то время как дальнейшее увеличение их числа снижает эффективность. Это объясняется значительными накладными расходами на обмен данными через MPI и ограничениями памяти, которые создают "узкие места" в производительности.

Увеличение объёма входного массива повышает долю времени, затрачиваемого на вычисления по сравнению с коммуникациями, но линейного ускорения это не обеспечивает.

По итогу, результаты показывают, что параллельная версия с использованием MPI может быть полезной для данной задачи, однако её масштабируемость ограничена архитектурными особенностями. Оптимальный эффект достигается при умеренном числе процессов.
