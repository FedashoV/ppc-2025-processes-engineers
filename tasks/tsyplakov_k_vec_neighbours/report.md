## 1. Введение  
---
В данной работе изучается задача определения пары соседних элементов вектора с наименьшей разницей между их значениями. Основная цель — реализовать как последовательный, так и MPI-параллельный алгоритм, провести сравнение их производительности на векторах различной длины и оценить, как обмен данными между процессами влияет на масштабируемость решения.

## 2. Постановка задачи
---
На вход подается вектор целых чисел. Необходимо определить такой индекс i, для которого разница между элементами с индексами i и i+1 минимальна. В качестве результата возвращается кортеж индексов (i, i+1).

### Дополнительные требования и ограничения:
1. Если встречаются несколько пар с одинаковой минимальной разницей, выбирается пара с индексом, который ближе к 0 (к началу вектора);
2. Алгоритмы должны корректно обрабатывать любые значения элементов вектора;
3. Для одинаковых входных данных последовательная и параллельная реализации должны возвращать одинаковый результат;
4. Параллельный алгоритм реализуется с использованием MPI и должен правильно работать.

## 3. Базовый алгоритм
---
Концепция такова, чтобы за один проход по вектору вычислить наименьший модуль разности соседних элементов. 

### Ход работы:
1. В конструкторе принимаем на вход вектор, а на выход ставим по умолчанию (-1, -1), что означает, что нету такой пары, которая удовлетворяла бы поставленную цель.
```
TsyplakovKVecNeighboursSEQ::TsyplakovKVecNeighboursSEQ(const InType& in) {
  SetTypeOfTask(GetStaticTypeOfTask());
  GetInput() = in;
  GetOutput() = std::make_tuple(-1, -1);
}
```
2. В следующем методе происходит проверка количества элементов в векторе (их должно быть не менее двух):
```
bool TsyplakovKVecNeighboursSEQ::ValidationImpl() {
  return GetInput().size() >= 2;
}

bool TsyplakovKVecNeighboursSEQ::PreProcessingImpl() {
  vector_data = GetInput();
  return true;
}
```
Также для удобства необходимо создать отдельную переменную для обработки входящего вектора, что и произошло в функции выше.

3. Реализуем поиск пары с минимальной разницей по значению. 
```
bool TsyplakovKVecNeighboursSEQ::RunImpl() {
  // Переменная, в которой будет храниться минимальная разница соседей.
  // В начале инициализируется максимальным возможным 32-битным числом.
  int min_diff = std::numeric_limits<int>::max();
  // Индекс элемента вектора, который выполняет наше условие.
  int min_index = -1; 

  for (size_t i = 0; i + 1 < vector_data.size(); i++) {
    int diff = std::abs(vector_data[i] - vector_data[i + 1]); 
    if (diff < min_diff) {
      min_diff = diff;
      min_index = static_cast<int>(i);
    }
  }

  if (min_index >= 0) {
    // в выходные данные записываем пару элементов, которая подходит под цель программы.
    GetOutput() = std::make_tuple(min_index, min_index + 1); 
  } else {
    GetOutput() = std::make_tuple(-1, -1);
  }

  return true;
}
```

## 4. Схема распараллеливания
---
Общая идея:

1) Вектор разделяется на блоки, которые обрабатываются разными процессами.
2) Каждый процесс ищет локальный минимум в своём блоке
3) Для проверки пар на границе блоков процессы должны иметь доступ к крайнему элементу соседнего блока.
4) Локальные результаты агрегируются с использованием операций ```MPI_Reduce + MPI_MINLOC``` для получения глобального минимума.
5) Итоговый результат доступен на всех процессах после рассылки ```(MPI_BCAST)```.

### Алгоритм параллельного выполнения:

<b>1: Инициализация:</b> все процессы запускаются в коммуникаторе ```MPI_COMM_WORLD```. Root-процесс ```rank=0``` проверяет валидность входного вектора и транслирует результат остальным процессам через ```MPI_BCast```.

<b>2: Распределение данных:</b> Каждому процессу назначается непрерывный диапазон элементов вектора. Размер блока рассчитывается как ```base = global_size / comm_size```, остаток распределяется по первым процессам ```(rem = global_size % comm_size)```. Начальный и конечный индексы блока вычисляются для корректного поиска локального минимума.

<b>3: Локальные вычисления:</b> Каждый процесс проходит по своему локальному вектору и вычисляет минимальную разницу соседних элементов. Если разница равна текущему минимальному значению, выбирается пара с наименьшим глобальным индексом.

<b>4: Агрегация результатов:</b> Глобальный минимум и индекс его первого элемента теперь вычисляются одной операцией ```MPI_Allreduce``` с оператором ```MPI_MINLOC```. Таким образом, глобальный результат доступен сразу всем процессам, без отдельного ```Reduce``` и ```Bcast```.

```
struct { int delta; int index; } send_res{local_res.delta, local_res.index}, recv_res;
MPI_Allreduce(&send_res, &recv_res, 1, MPI_2INT, MPI_MINLOC, MPI_COMM_WORLD);

if (recv_res.index >= 0) {
    GetOutput() = std::make_tuple(recv_res.index, recv_res.index + 1);
} else {
    GetOutput() = std::make_tuple(-1, -1);
}
```

<b>5: Выходные данные:</b> Если глобальный индекс найден, то он используется для формирования пары соседей ```(i, i + 1)``` и сохраняется в ```GetOutput()``` на всех процессах. В противном случае результат остаётся ```(-1, -1)```.

### Топология процессов:
Все процессы равноправны для вычисления локальных минимумов и обмена границами. Root-процесс дополнительно выполняет распределение данных. В последствии глобальный результат доступен на всех процессах.

### Особые случаи

К особому случаю можно отнести обработку пограничных значений между процессами. Каждый процесс получает диапазон элементов вектора:
```
int base = global_size / comm_size;
int rem = global_size % comm_size;
int local_start = rank * base + std::min(rank, rem);
int local_end = local_start + base + (rank < rem ? 1 : 0);
```
Далее процесс вычисляет локальный минимум разницы между соседними элементами на своём участке:
```
Result local_res{std::numeric_limits<int>::max(), -1};

for (int i = local_start; i + 1 < local_end; ++i) {
    int diff = std::abs(vec[i + 1] - vec[i]);
    if (diff < local_res.delta || (diff == local_res.delta && i < local_res.index)) {
        local_res.delta = diff;
        local_res.index = i;
    }
}
```
Чтобы корректно учитывать пары, которые пересекают границы блоков, происходит обмен граничными элементами между соседними процессами:
```
int left_value  = (local_start > 0) ? vec[local_start] : 0;
int right_value = (local_end < global_size) ? vec[local_end - 1] : 0;

int recv_left = 0, recv_right = 0;
MPI_Request reqs[4] = {MPI_REQUEST_NULL, MPI_REQUEST_NULL, MPI_REQUEST_NULL, MPI_REQUEST_NULL};
int rc = 0;

if (rank > 0) {
    MPI_Irecv(&recv_left, 1, MPI_INT, rank - 1, 0, MPI_COMM_WORLD, &reqs[rc++]);
    MPI_Isend(&left_value, 1, MPI_INT, rank - 1, 1, MPI_COMM_WORLD, &reqs[rc++]);
}
if (rank + 1 < comm_size) {
    MPI_Irecv(&recv_right, 1, MPI_INT, rank + 1, 1, MPI_COMM_WORLD, &reqs[rc++]);
    MPI_Isend(&right_value, 1, MPI_INT, rank + 1, 0, MPI_COMM_WORLD, &reqs[rc++]);
}

if (rc > 0) MPI_Waitall(rc, reqs, MPI_STATUSES_IGNORE);
```
После завершения обмена каждый процесс проверяет возможные минимальные разницы на границах:
```
if (rank > 0) {
    int diff = std::abs(left_value - recv_left);
    int idx = local_start - 1;
    if (diff < local_res.delta || (diff == local_res.delta && idx < local_res.index)) {
        local_res.delta = diff;
        local_res.index = idx;
    }
}

if (rank + 1 < comm_size) {
    int diff = std::abs(right_value - recv_right);
    int idx = local_end - 1;
    if (diff < local_res.delta || (diff == local_res.delta && idx < local_res.index)) {
        local_res.delta = diff;
        local_res.index = idx;
    }
}
```
Таким образом, локальный минимум учитывает все пары соседних элементов, даже включая пары на границах блоков.

### Пространственная и временная сложности алгоритмов

<b>Последовательная версия:</b>

Временная сложность составляет ```O(N)```, где  ```N``` - размер вектора.\
Пространственная сложность - ```O(N)```, где ```N``` - размер вектора индексов, равный размеру входного вектора.

<b>Параллельная версия:</b>

Временная сложность - ```O(N/P + log(P))```, где ```N``` - размер вектора, ```P``` - количество процессов, ```log(P)``` - сложность операции ```MPI_Reduce```.\
Пространственная сложность - ```O(N/P)``` на процессах, связанных с вычислениями и ```O(N)``` на Root-процессах.

## 8. Выводы
---

В рамках работы был разработан и протестирован алгоритм поиска пары соседних элементов вектора с минимальной разницей значений, реализованный как в последовательной, так и в параллельной версиях.

Параллельная реализация позволила распределить вычислительные задачи между несколькими процессами и сократить время выполнения, однако полученное ускорение оказалось ограниченным. Наибольший прирост производительности наблюдается при использовании двух процессов, в то время как дальнейшее увеличение их числа снижает эффективность. Это объясняется значительными накладными расходами на обмен данными через MPI и ограничениями памяти, которые создают "узкие места" в производительности.

Увеличение объёма входного массива повышает долю времени, затрачиваемого на вычисления по сравнению с коммуникациями, но линейного ускорения это не обеспечивает.

По итогу, результаты показывают, что параллельная версия с использованием MPI может быть полезной для данной задачи, однако её масштабируемость ограничена архитектурными особенностями. Оптимальный эффект достигается при умеренном числе процессов.
